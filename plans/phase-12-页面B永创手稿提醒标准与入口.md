# phase-12-页面B永创手稿提醒标准与入口

## 1. 目标
- 建立页面 B 的第一阶段：只服务永创手稿提醒。
- 页面 B 第一阶段要能吃一份标准 Excel，展示永创手稿里的待催提醒。
- 页面 B 要和页面 A 保持同一套视觉风格，先总览，再按客户卡片进入，再看明细。
- 管理员后台新增独立入口 `手稿提醒导入（仅页面B）`，用于上传页面 B 标准 Excel。
- 做完后，月总能用手工整理好的标准 Excel 验证：页面 B 能显示提醒，且不影响页面 A 的金蝶提醒。

## 2. 当前状态
- 页面 A 是当前手机端/前端的金蝶提醒展示页，只展示金蝶数据生成的 `发货超过 60 天未开票`。
- 页面 A 必须保持干净、只读、无互动；页面 A 数据错误时回金蝶源头修正，不在 A 页面直接改。
- 页面 B 是后续工作台，用于承接提醒查看、状态、跟进记录等工作行为。
- 2026-07-10 02:13 (Asia/Shanghai) 已查明：当前 `龙虾异步任务（对接层）` 不是手稿上传入口。
  - 后端有 `/v1/tasks/lobster-feed` 和 `lobster_connector`，但它只是旧兼容/编排触发入口。
  - 前端只有 `启动 lobster-feed`、`刷新任务`，不提供文件上传，也不承接手稿数据。
- 月总已决定：不改 1 号现有金蝶上传区域，不改 2 号龙虾区域；在二者之间新增独立手稿入口区域。
- 第一阶段只做永创，不碰联合工具/联合电器，不碰巨星系。

## 3. 边界和不做什么
- 本 phase 只做页面 B 的永创手稿提醒标准与入口。
- 本 phase 不接入页面 A 的金蝶提醒数据到页面 B。
- 本 phase 不做 `金蝶待更新`、`金蝶已同步`、金蝶提醒跟进记录。
- 本 phase 不把老婆手稿数据写进页面 A 的金蝶提醒主链路。
- 本 phase 不把手稿数据和页面 A 的金蝶数据自动合并。
- 本 phase 不改现有 1 号 `人工上传（四类输入）` 的金蝶上传逻辑。
- 本 phase 不改现有 2 号 `龙虾异步任务（对接层）` 的旧兼容逻辑。
- 本 phase 不做手稿清洗小软件；清洗小软件应在后续独立 phase 做，并放到独立项目目录，不能污染当前软件仓库。
- 本 phase 不做 Git 推送、不做阿里云发布，除非月总另行明确下令。

## 5. 里程碑 / 施工步骤
1. 建立页面 B 的手稿提醒数据模型。
   - 支持标准 Excel 字段。
   - 支持来源字段。
   - 支持状态：`待催`、`已联系`、`不再提醒`。
   - 字段缺失时页面显示 `缺失`，不留空、不隐藏、不推算。
2. 新增管理员后台入口。
   - 入口名称固定为：`手稿提醒导入（仅页面B）`。
   - 提示语固定为：`只进入页面B工作台，不影响页面A（金蝶提醒）。`
   - 页面位置：放在现有 1 号 `人工上传（四类输入）` 和 2 号 `龙虾异步任务（对接层）` 中间。
   - 不复用龙虾业务含义。
3. 定义并接入标准 Excel。
   - 字段固定为：
     - 客户
     - 合同号/订单号
     - 产品
     - 未开数量
     - 未开金额
     - 已开数量
     - 已开金额
     - 订单时间
     - 来源
     - 状态
   - 本字段清单是本 phase 必须完成的完整标准，不是临时残版。
4. 建立页面 B 手机端展示。
   - 布局参照页面 A。
   - 顶部汇总固定显示：`待催客户`、`待催金额`、`最久已超`、`来源`。
   - 第一屏汇总下面按客户卡片进入。
   - 客户卡片显示：客户名、待催金额、共几笔、最久已超、来源。
   - 进入客户后，明细按订单时间排序。
5. 建立明细卡。
   - 明细卡字段顺序固定为：
     - 合同号/订单号
     - 产品
     - 未开数量
     - 未开金额
     - 已开数量
     - 已开金额
     - 订单时间
     - 来源
   - 任何源数据没有的字段，固定显示 `缺失`。
6. 建立状态操作。
   - 支持 `待催`。
   - 支持改为 `已联系`。
   - 支持改为 `不再提醒`。
   - `不再提醒` 的记录不在主提醒列表展示，但不能删除，后续应能在单独清单找回。
7. 用永创样本验收。
   - 上传一份符合标准 Excel 的永创手稿提醒文件。
   - 页面 B 能按客户汇总和明细展示。
   - 页面 A 的金蝶提醒不变。

## 6. 验收路径
- 管理员后台：
  1. 打开 `/ops-admin/`。
  2. 确认 1 号现有上传区域仍是 `人工上传（四类输入）`。
  3. 确认 2 号龙虾区域仍不被当成手稿入口。
  4. 确认二者之间出现独立区域：`手稿提醒导入（仅页面B）`。
  5. 确认提示语为：`只进入页面B工作台，不影响页面A（金蝶提醒）。`
  6. 上传标准 Excel 后，能看到导入结果和错误提示。
- 页面 B：
  1. 打开页面 B 手稿提醒入口。
  2. 顶部汇总显示 `待催客户`、`待催金额`、`最久已超`、`来源`。
  3. 第一屏下面显示客户卡片，不直接平铺全部明细。
  4. 客户卡片显示客户名、待催金额、共几笔、最久已超、来源。
  5. 点客户卡片进入详情后，明细按订单时间排序。
  6. 明细卡按固定顺序展示：合同号/订单号、产品、未开数量、未开金额、已开数量、已开金额、订单时间、来源。
  7. 数据源缺失字段显示 `缺失`。
  8. 状态支持 `待催`、`已联系`、`不再提醒`。
  9. `不再提醒` 后，主提醒列表不再显示该记录，但记录仍可追溯。
- 防污染验收：
  1. 导入手稿提醒前后，页面 A 的金蝶提醒客户数、金额、天数和导出 Excel/HTML 口径不变。
  2. 页面 B 修改状态后，页面 A 不变。
  3. 页面 B 删除/隐藏主提醒展示后，页面 A 不变。
